You are acting as a senior full-stack developer, product strategist, UX designer, and SEO-minded builder.


Build a simple, polished, production-ready website called “Color Palette Generator”.


The website should be a fast, client-side color palette generator for designers, developers, marketers, content creators, indie hackers, students, and anyone who needs attractive color combinations quickly.


The site should work as a standalone web app inside this repo. Make reasonable decisions without asking follow-up questions unless something is truly blocking.


PROJECT GOAL


Create a clean, modern website where users can generate beautiful color palettes, copy color codes, lock individual colors, export palettes, check basic accessibility contrast, and save favorite palettes locally.


The site should feel like a useful free design tool, not a generic landing page.


WHAT THE WEBSITE DOES


The website lets users:


1. Generate a 5-color palette instantly.
2. Generate a random palette.
3. Enter a seed color using a HEX input or color picker.
4. Choose a harmony mode:
   - Random
   - Monochromatic
   - Analogous
   - Complementary
   - Triadic
   - Tetradic
   - Pastel
   - Vibrant
   - Dark
5. Lock individual colors so they stay unchanged when generating again.
6. Copy a color value with one click.
7. View each color as:
   - HEX
   - RGB
   - HSL
8. See basic contrast guidance for text on each color:
   - Best text color: black or white
   - Contrast ratio against black
   - Contrast ratio against white
   - Simple WCAG-style label: “Good for text”, “Use carefully”, or “Decorative only”
9. Export the palette as:
   - CSS variables
   - Tailwind config snippet
   - JSON
   - SVG swatch strip
10. Save favorite palettes in localStorage.
11. Reopen saved palettes.
12. Delete saved palettes.
13. Share a palette through a URL query string, for example:
   - /?palette=264653,2A9D8F,E9C46A,F4A261,E76F51

COLOR LOGIC REQUIREMENTS


Create robust color utility functions in /lib/color.ts:


Functions should include:
- normalizeHex(input): returns valid 6-character uppercase HEX with # removed or null.
- hexToRgb(hex)
- rgbToHex(r, g, b)
- rgbToHsl(r, g, b)
- hslToRgb(h, s, l)
- hslToHex(h, s, l)
- getRelativeLuminance(rgb)
- getContrastRatio(colorA, colorB)
- getBestTextColor(hex): returns black or white
- isValidHex(input)


Palette generation in /lib/palette.ts:
- generatePalette(options)
- generateRandomPalette()
- generateMonochromatic(seed)
- generateAnalogous(seed)
- generateComplementary(seed)
- generateTriadic(seed)
- generateTetradic(seed)
- generatePastel(seed optional)
- generateVibrant(seed optional)
- generateDark(seed optional)
- applyLocks(existingPalette, newPalette, lockedMap)


Generation rules:
- Always return exactly 5 colors.
- Never return invalid HEX values.
- Avoid palettes where all colors are nearly identical unless monochromatic mode is selected.
- Keep hue values wrapped correctly between 0 and 360.
- Clamp saturation and lightness safely.
- If no seed color is provided, generate a random seed.
- Preserve locked colors when regenerating.
- If all 5 colors are locked and user clicks generate, show a friendly message: “Unlock a color to generate new options.”

KEY EDGE CASES


Handle these edge cases:


1. Invalid HEX input:
   - Show friendly validation.
   - Do not crash.
   - Example message: “Enter a valid HEX color like #4F46E5.”


2. HEX input without #:
   - Accept it and normalize it.


3. Short HEX like #FFF:
   - Accept and expand to #FFFFFF if you choose to support it.
   - If not supporting short HEX, show clear validation.


4. Locked colors:
   - Preserve locked colors on generation.
   - If all colors are locked, do not regenerate. Show a helpful message.


5. localStorage unavailable:
   - App should still work.
   - Show message that saving is unavailable in this browser mode.


6. Malformed URL palette:
   - Ignore invalid colors.
   - Fall back to a generated palette.


7. Duplicate saved palette:
   - Do not save the same exact palette twice.
   - Instead show “Already saved.”


8. Very light or very dark colors:
   - Ensure text on cards remains readable by choosing black or white text.


9. Mobile screens:
   - Controls should not overflow.
   - Cards should stack cleanly.


10. Clipboard API unavailable:
   - Gracefully fall back or show “Copy not available in this browser.”


11. Hydration issues:
   - localStorage should only be accessed client-side.


12. No JavaScript disabled:
   - At minimum, show the static page content.
   - The generator can require JavaScript.
