# Programmatic enforcement of agent process guidance, and triggers for unmet needs — survey

Researcher memo, 2026-09-04 (mu-96ga9 follow-up). Fixed context taken as given: 15-run mu battery (qwen3.8-27b non-thinking), 0 plan / 0 discover calls despite a 10 KB AGENTS.md; two runtime-shaped failures (guard refusals never ending the turn; bash timeout not killing the test binary).

## 1. Harness-level gates: what is enforced vs suggested

- **Claude Code hooks** are the enforcement layer; the prompt is not. PreToolUse exit 2 blocks the call and stderr is fed to the model as the reason; PostToolUse exit 2 only shows stderr (the tool already ran); Stop exit 2 prevents stopping ([hooks](https://code.claude.com/docs/en/hooks)). Plan mode is prompt-only ("MUST NOT" in caps); writes slipped through, and the fix was a PreToolUse hook denying Write/Edit in plan mode ([sondera](https://blog.sondera.ai/p/claude-codes-plan-mode-isnt-read)).
- **Claude Code TodoWrite** is structure plus nudge: the description carries the invariant ("Exactly ONE task must be in_progress at any time"; don't mark complete if tests fail) ([description](https://github.com/Piebald-AI/claude-code-system-prompts/blob/main/system-prompts/tool-description-todowrite.md)); the harness injects event-driven system reminders when the list goes stale ([reminders](https://michaellivs.com/blog/system-reminders-steering-agents/)); users report over-firing and performative todo calls ([#56415](https://github.com/anthropics/claude-code/issues/56415)). Loop detection was requested and closed not-planned ([#4277](https://github.com/anthropics/claude-code/issues/4277)).
- **SWE-agent ACI**: edit rejected when it introduces lint errors: 18.0% vs 15.0% without; collapsing old observations to one line 18.0% vs 15.0%; 100-line window vs full file 18.0% vs 12.7% ([paper](https://arxiv.org/abs/2405.15793)). Format errors have a budget (3) then autosubmit.
- **OpenHands**: stuck detector (4 repeated action-observation, 3 action-error, 3 monologue, 6 alternating) ([docs](https://docs.openhands.dev/sdk/guides/agent-stuck-detector)); LLM condenser cuts cost up to 2x with no measured degradation ([condenser](https://docs.openhands.dev/sdk/guides/context-condenser)).
- **Codex CLI**: OS-enforced sandbox, approvals second ([doc](https://learn.chatgpt.com/docs/agent-approvals-security)); planning is an `update_plan` tool with pending/in_progress/done in the tool list ([#1952](https://github.com/openai/codex/issues/1952)), the DeepSeek todo_write shape. **Cursor** hooks return allow/ask/deny with an agent_message; its stop hook cannot block ([hooks](https://cursor.com/docs/hooks)). **Aider** auto-lints/auto-tests after every edit and feeds failures back, capped at 3 reflections ([lint-test](https://aider.chat/docs/usage/lint-test.html)).
- **LangChain deep agents**: model fixed, a PreCompletionChecklistMiddleware (verify before exit), LoopDetectionMiddleware (per-file edit counter, nudge after N) and startup context injection took Terminal Bench 2.0 from 52.8% to 66.5% ([post](https://www.langchain.com/blog/improving-deep-agents-with-harness-engineering)).

## 2. Loop/stuck detection with termination

- **OpenHands SDK**: on action-error streaks first a nudge; if `is_stuck()`, status STUCK and the run loop breaks; `max_iteration_per_run` (500) sets ERROR and breaks ([local_conversation.py](https://github.com/OpenHands/software-agent-sdk/blob/main/openhands-sdk/openhands/sdk/conversation/impl/local_conversation.py)). False positive: agents waiting on long processes ([#5355](https://github.com/OpenHands/OpenHands/issues/5355)).
- **Gemini CLI** halts outright ("A potential loop was detected… halted"), with enough false positives to add a disable option ([#8928](https://github.com/google-gemini/gemini-cli/issues/8928)).
- **SWE-agent** ends every limit path in autosubmit of the partial diff (`exit_cost`, `exit_context`, `exit_format`) ([output files](https://mini-swe-agent.com/latest/usage/output_files/)).
- **Framework caps**: LangGraph `recursion_limit` 25 raises; `RemainingSteps` lets a node end gracefully ([docs](https://docs.langchain.com/oss/python/langgraph/errors/GRAPH_RECURSION_LIMIT)). OpenAI Agents SDK `max_turns` with an error handler for a controlled final output ([docs](https://openai.github.io/openai-agents-python/running_agents/)).
- **In-band then out-of-band**: a signature guard (hash of tool + normalized args, trips at 3) returns the block as the tool observation, backed by a hard `max_steps` outer rail ([metaheuristic](https://www.metaheuristic.co/blog/preventing-tool-call-cycles/)). mu had the guard and not the rail.

## 3. Trigger designs that create an unmet need

- **Tool-list stub + deferred tools**: only the search tool and 3-5 core tools visible; Opus 4 49% → 74%, 85% fewer tool tokens; selection degrades past 30-50 visible tools ([tool search](https://platform.claude.com/docs/en/agents-and-tools/tool-use/tool-search-tool)). Claude Code's deferred tools show the failure mode: calling a name-only tool gives InputValidationError; "ToolSearch required but not enforced" is filed as a bug ([#60052](https://github.com/anthropics/claude-code/issues/60052)). The refusal must carry the redirect.
- **First-action gates**: `tool_choice` required/named on turn 1, then auto; Manus masks logits by state ("mask, don't remove") and rewrites todo.md so goals are recited at the end of context ([Manus](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus)). vLLM supports named/required tool_choice for Qwen via the hermes parser; guided decoding has open bugs with Qwen3 thinking off ([#18819](https://github.com/vllm-project/vllm/issues/18819), [#27447](https://github.com/vllm-project/vllm/issues/27447)).
- **Budget reminders**: Anthropic injects a token budget and, after every tool call, `<system_warning>Token usage: …; … remaining</system_warning>` for 4.5-class models ([context windows](https://platform.claude.com/docs/en/build-with-claude/context-windows)).
- **Verification gates**: Stop hook blocks once when Write/Edit appeared this turn, `stop_hook_active` lets the second pass through ([quality gates](https://fbakkensen.github.io/ai/devtools/development/2026/03/27/quality-gates-for-coding-agents-how-stop-hooks-make-validation-mandatory.html)); Anthropic's long-running harness marks every feature "failing" in a JSON list because models mark features complete without testing ([harnesses](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)).
- **Small-model evidence**: AgentIF: best model follows tool-spec constraints 26.9%; near 0 past 6,000 words ([AgentIF](https://arxiv.org/abs/2505.16944)). SOPBench: top models 30-50% SOP compliance, 7-8B significantly worse ([SOPBench](https://arxiv.org/abs/2503.08669)). Structure helps at the bottom: constrained decoding raises accuracy up to 4% even on GSM8K down to Llama-3.2-1B ([JSONSchemaBench](https://arxiv.org/html/2501.10868v1)). Caveat: a schema that forces the answer before reasoning drops LLaMA-3-8B Last Letter 70% → 28% ([Let Me Speak Freely](https://arxiv.org/html/2408.02442v1)).

## 4. Why prose rules fail

- **Compliance gap**: six frontier models, 0% compliance with a process instruction by default; Sonnet 4 "verbally agrees ten out of ten times then bypasses in all ten"; removing the bypass tool raised compliance to 75% ([paper](https://arxiv.org/abs/2605.01771)).
- **Context files**: AGENTS.md does not improve success and adds >20% cost ([Gloaguen](https://arxiv.org/abs/2602.11988)); a two-agent ablation bounds the correctness effect near zero ([ablation](https://arxiv.org/html/2607.27250)); size/position of the file have no detectable effect, compliance odds fall 5.6% per function generated within a session ([factorial](https://arxiv.org/abs/2605.10039)). OctoBench: "systematic gap between task-solving and scaffold-aware compliance" ([OctoBench](https://arxiv.org/abs/2601.10343)).
- **Density and length**: IFScale shows decay with instruction count and bias toward earlier instructions ([IFScale](https://arxiv.org/abs/2507.11538)); Chroma's 18-model study (incl. Qwen3) shows monotone degradation and single-distractor harm ([context rot](https://www.trychroma.com/research/context-rot)).
- **Schema salience**: small perturbations to tool descriptions shift selection ([BiasBusters](https://openreview.net/forum?id=DEg4vvElYu), [ToolTweak](https://arxiv.org/abs/2510.02554)); the extreme is grammar-constrained sampling ([strict tool use](https://platform.claude.com/docs/en/agents-and-tools/tool-use/strict-tool-use)).

## Recommendations for mu (ranked)

1. **Loop guard with a ladder and a floor.** Repeat 1-2: block as the tool observation stating count and "result unchanged". Repeat 3: strip or mask that tool for the next call. Repeat 5 or hard step budget: end the turn with status STUCK and submit partial work. Risk: false positives on legitimate polling; compare observation too, exempt read-only calls.
2. **Fix the runtime, not the prompt.** Bash in its own process group, kill the group on timeout, exit code plus timeout marker in the structured result. Risk: killing wanted background servers; give them an explicit background tool.
3. **One-shot verification gate at end-of-turn.** If a source edit happened after the last green test run, refuse the stop once with "tests have not run since your last edit", then let the second through. LangChain's checklist middleware is the largest single lever in their +13.7. Risk: over-gating on tasks without a test command; condition on a known test command and a source edit.
4. **Plan as a schema, triggered by tool_choice, not a directive.** todo_write with replace semantics and the one-in_progress invariant in the description; for tasks above a size threshold force it as the first call via named tool_choice, or mask edit/write until a plan exists. Risk: performative todos and cost; verify tool_choice on the vLLM/Qwen3 non-thinking stack first.
5. **Discovery by refusal-with-redirect.** 3-5 core tools plus a `discover` stub visible; everything else name-only and a direct call returns "not loaded; call discover select:<name>". Turns "call discover first" from prose into the only executable path. Risk: an extra round trip per new tool and search misses; keep core tools undeferred.
6. **Cut the context that carries procedure.** Drop process prose from AGENTS.md (keep non-standard repo facts), collapse tool observations older than N turns to one line, inject "N steps remaining" after each tool result. Risk: losing needed repo facts; keep facts, remove procedure.
